# 經驗教訓（管線踩過的坑）

2026-09 做頭頸部、呼吸系統、免疫疾病三門課時學到的事；第 12、13 節是 2026-10 做 uro-a3 時加的。每條寫「發生什麼 → 現在怎麼做」。投影片風格上的教訓在 `style/guide/40_範例/43_反例庫.md`，這裡只寫工具與流程。

## 1. 換行字元（CRLF）

- **發生什麼**：Claude Code 的 Workflow 工具拒絕含 `\r` 的腳本。Windows 上的 Python 寫檔預設 CRLF；Git for Windows 預設 `core.autocrlf=true`，clone 下來的 .js 也會變成 CRLF。
- **現在怎麼做**：
  - clone 時加 `-c core.autocrlf=false`（已 clone 的：`git config core.autocrlf false` 後重新 checkout）；
  - Python 寫文字檔一律 `open(path, "w", encoding="utf-8", newline="\n")`；
  - 跑工作流前檢查：`grep -c $'\r' workflows/*.js` 全部要是 0。

## 2. 續跑：DONE 表，而不是 resumeFromRunId

- **發生什麼**：額度在工作流中途用完好幾次（immune 的風格挖掘、藍圖、撰寫都停過）。`resumeFromRunId` 只能沿用「從頭算起沒改動的那一段 agent() 呼叫」，而且要在同一台電腦、run 的紀錄還在；當時為了改用 Opus 而改了每個代理的 model，第一個呼叫就不同，結果整批重跑。
- **現在怎麼做**：每支工作流都支援 `args.done = {"<label>": "<輸出檔路徑>"}`，列在裡面的代理直接回傳舊檔、不呼叫模型，log 會出現 `reuse (not re-run): <label>`。
  - 重建 DONE 表一律用 `workflows/tools/done_from_journal.py`：有 journal 就讀 journal（Claude Code 本機在 `~/.claude/projects/<專案>/<session>/subagents/workflows/<runId>/journal.jsonl`）；journal 不見了（雲端 VM 被回收）就用 `--scan` 依輸出檔名推回 label（例：`batch_3_check_voice.json` → `voice:3`）。
  - 被中斷當下正在跑的代理要重跑（它的輸出檔可能不完整，用 `--drop`）。
  - journal、當次 args 與 DONE 表都存在課程的 `_archive/journals/` 並 commit（`workflows/README.md`「續跑」）。
- 任何代理回傳 null（多半是額度用完）時，腳本停止派新代理；不要自動重試，等使用者同意再續跑。

## 3. 換行量測要用真的字型

- **發生什麼**：早期用「全形 1.0、半形 0.55 個字寬」估算換行，實際在 PowerPoint 裡常多一行而溢出；審查者用估算判斷「放得下」的改法，渲染後三條都放不下（immune 第二輪）。
- **現在怎麼做**：`gen_pptx.py` 用實際字型量測每一行（Windows 用微軟正黑體，雲端用 Noto Sans CJK TC，都沒有才退回估算），粗體另量；行高係數 1.12；表格列高含上下邊界；關掉 `hangingPunct`；left 版型文字欄依內容從 47% 自動加寬到 65%；條列區扣掉左下「資料來源」的高度；圖片不壓到出處。雲端量測字型與 PowerPoint 實際字型不同，最後仍要在 Windows 的 PowerPoint 看一次。

## 4. 綠燈不算數：一定要看 PNG

- **發生什麼**：check_deck ALL GREEN、style_check RED 0 的版本，渲染後仍有溢出、孤字、行首標點、英文字中間斷行、圖被壓小、圖說蓋到出處。
- **現在怎麼做**：每次重產都 `export_pdf.py --pngs` 出逐張 PNG 並實際看（先看縮圖拼板，再放大可疑張）；審查工作流有專門看 PNG 的 layout 面向；「估算放得下」的修正要渲染過才算完成。

## 5. 掃描版教科書的切圖

- **發生什麼**：Robbins 的章節 PDF 是掃描檔，`get_images()` 抽不到圖（頁面由數十條水平掃描帶拼成）；有的檔文字層是自訂編碼（字元落在 PUA 0xF0xx，解碼為 `chr(288 - (code & 0xff))`，0xF020 是空白；呼吸系統那一章就是這樣，這個解碼模式沒有收進 `robbins_crop.py`，遇到時走下面的 OCR 路線即可）；有的檔沒有文字層，只有浮水印。
- **現在怎麼做**：
  - 先把每頁渲染成圖（`render_pdf_pages.py`，約 200 dpi），用 Tesseract OCR 產文字與字詞座標（.txt、.tsv）；
  - `robbins_crop.py` 以 OCR 找「Fig. N.M」「Table N.M」圖說的位置，圖在圖說正上方，圖說寬度限制水平範圍；
  - 側邊圖說、反白圖說、label 與圖說分成兩塊、圖說縮排的圖，用 `--ovr` JSON 手動給 200 dpi 像素座標（immune 46 圖＋17 表，19 圖與全部表格用了手動座標）；
  - 多面板圖拆 A／B／C；一定要看 `contact_*.png` 拼板確認；
  - 舊講義裡的截圖常常就是 Robbins 舊版的圖，出處要寫 Robbins，並對照 11e 的圖號。
- 教科書 PDF 常超過 100 MB，不放 repo；只 commit 頁圖、OCR 與切圖（都在私人 repo）。

## 6. 國考題庫的解析

- **考選部網站**：「考畢試題查詢平臺」是 ASP.NET WebForms，要先 GET 取 `__VIEWSTATE`，選年度要 postback 才會列出考試代碼；下載 PDF 要在同一個 session cookie 內、帶 Referer，否則轉址到 NotFound（`fetch_moex_dent_exam.py` 已處理）。
- **PDF 文字層的瑕疵**（`parse_moex_exam.py` 已處理並印警告）：康熙部首區字元（例「⽣」）要 NFKC 還原；部首補充區（例「⻑」）用對照表還原；Big5 延伸碼位衝突讓圈號 ①–⑩ 變成西里爾字母；題號用「循序期待」切題，避免題幹以數字開頭時誤切；英文在 PDF 換行處要補空格；上標數字要接回。
- **答案**：更正檔（`_M.pdf`）要套用；一律給分記 `#`，複選給分記 `A,C`。選題時避開 `#`、多答案、題幹寫「如附圖」而題庫沒有圖的題。
- **醫師題庫只收病理段（題號 76–100）**；原本的 `questions-115-2.json` 來源 PDF 標頭寫的是「115 年第一次」，76–100 題與 115-1 的題幹、答案相同（只差空白），是重複卷。2026-10-14 已刪掉，換成從考選部重抓的真正 115 年第二次試卷（考試代號 115090；試題代號 2301 與 115-1 相同，要看 PDF 標頭的「第二次」與類科「醫師(一)」，不能只看代號；見 `question_banks/README.md`）。
- **年次題號一律由題庫 key 產生**：他舊投影片的年次標籤有 17 題與題庫不符，沿用舊張時要列清單。
- 題庫文字先 NFC 正規化；官方原文的錯字照抄，在講稿註明。

## 7. 單一事實來源與覆蓋風險

- 藍圖與撰寫 JSON 經過審查修改後就過時了；再拿它們跑 `assemble.py` 會蓋掉審查改過的 pool.md。組裝只在撰寫階段做一次。
- 他親手改過的檔是權威版本。重產前沒回灌，會把他的修改蓋掉（頭頸部與呼吸系統都差點發生）。回灌時：以 slug 或備註表頭配對、他刪的張只從選單或該班 `aud` 拿掉、複製出的同標題連張各存各的內容、PPTX 備註不寫回 script.md、先清掉被圖蓋住的佔位殘留文字。
- 素材池的 `<!-- … -->` 註解裡不能出現 `>`（例如 `=>`），會把註解截斷。
- glossary 的禁用變體不要收他親手寫過的字形，否則檢查器會擋他的寫法。
- 新的檢查 regex 先對他自製的檔跑一次；會命中他自己句子的規則，改寫或降級成 WARN（舊版 rules.yaml 曾把他的「沙包或磚頭」判成違規）。

## 8. 審查工作流

- 每個面向一位審查、兩位獨立反駁，只做一輪：兩位都推翻的不套用，都確認的套用，一推一留由修正者回原始資料查過再決定（硬規則 16）；兩位給不同改法時，選較忠於 Robbins 與他原句的。
- 修正互相衝突時：事實 ＞ 術語 ＞ 版面 ＞ 文風；圖片與國考題的修正讓位。
- 課程明令優先於審查建議（例：審查建議某術語只寫英文，但該課明令每張中英對照，就不套用）。
- immune：第一輪 206 條、確認 192、套用 173；第二輪 129 條、確認 126、套用 117。第二輪仍有價值，但額度緊時一輪即可。

## 9. Windows 環境的小坑

- Python 印中文要設 `PYTHONIOENCODING=utf-8`，否則 cp950 報 `UnicodeEncodeError`。
- 在 Windows 的 shell 裡寫超過約 100 行的 heredoc 會被截斷（報 unexpected EOF）；大檔先存成檔再執行（Claude Code 用 Write 工具）。
- PowerPoint 匯出 PDF 前先關掉開著的同名 PPTX；`export_pdf.py` 用 PowerShell 呼叫 PowerPoint，不需要 pywin32。

## 10. 檔案大小與 GitHub

- immune 184 張的 PPTX 約 58 MB，幾乎全是圖。GitHub 單檔上限 100 MB（50 MB 以上警告），網頁上傳限 25 MB。
- 接近上限時：分節輸出（`gen_pptx.py --section N`，檔名自動加「_第N節」，不會蓋掉全套檔）或把圖先降到投影片實際需要的解析度再放進素材池。
- 成品 PPTX 預設不進 git（`.gitignore`）；交件的那一個用 `git add -f`，同名 `_layout.json` 照常提交（回灌時對 slug 用）。只提交交給老師的版本（毛胚、草稿），中途重產的不提交，repo 歷史才不會一直長大（SOP 第 10 步）。
- 教科書 PDF 放 repo 外；私人 repo 的 `.gitignore` 排除成品以外的所有 PDF。

## 11. 額度與費用管理

- 花費幾乎都在多代理工作流；每個代理都要讀事實帳、指南、頁圖等大檔。immune 整門課約 200 個代理（蒐集 97、藍圖 10、撰寫 57、審查兩輪 38），以 API 牌價換算約 $950–1,200；風格挖掘約 89、風格指南約 49 已完成不必重跑。
- 開跑前先空跑數出代理數上限，照上限報代理數與費用、等使用者同意；分次跑、看用量；停下時存 DONE 表並 commit。
- 四階段做法（uro-a3）的實測與各角色的花費占比見 `workflows/README.md`「代理數與費用」「角色與強度」。
- 先用小階段（藍圖 10 個代理）量出每個代理的平均花費，再估整門課。
- 扣款順序：雲端 session 先扣雲端 session 額度（2026-09 送的一次性額度，會過期）→ 用完改吃方案用量（與本機共用）→ 使用者打開「usage credits」開關時才扣買的 credits。本機 session 不會用到雲端額度，所以方案每週用量吃緊時，把重的工作流放雲端。
- 雲端 VM 閒置會被回收，正在跑的代理與沒 push 的檔案會不見；每個階段結束就 commit＋push。
- 詳見 `docs/cloud_session_教學.md` 第 9 節。

## 12. 強度會繼承主 session（2026-10-14）

  - kit 的通用工作流只吃 `args.effort`（lecture-gather 另收 `effort_hard`、`effort_light`）：叫它們時一定要給。
  - 課程自寫的腳本：用 grep 確認每個 `agent()` 都有 effort；kit 的通用工作流：確認 args 有 `effort`。2026-10-30 起 `wf_check_mac.js` 印出每個代理的 effort 與 `no_effort`，空跑時直接看。

## 13. 多輪反駁會讓費用失控（2026-10-14）

- **發生什麼**：教師說，之前費用失控最嚴重的那門課（lung），錢幾乎都花在用比 opus 更貴的型號跑的多輪反駁。uro-a3 初稿 57 個代理的反駁只跑一輪、每份批評檔 2 位、全部用 opus，沒有那種反駁循環；但它的牌價換算下限約 $268（不含 output），不比 immune 省，事實複查與事實反駁仍占 Workflow 回報的 subagent_tokens 的 22%（11.7%＋10.5%），複查兩輪也都看整批。10/15 凌晨充實版和另一個工作流一起跑，還是用完了一次方案額度。
- **現在怎麼做**：硬規則 16 的上限（反駁一輪、每份批評檔 2 位、不反駁反駁者；複查最多 2 輪、第 2 輪只看改過的張、第 1 輪沒有事實問題就停）；模型一律 opus，不換成更貴的型號；開跑前空跑拿代理數上限再報價（`workflows/README.md`「反駁與複查的上限」）。

## 14. 過度審查：同一份內容查兩遍（2026-10-15）

- **發生什麼**：uro-a3 的充實工作流（階段 3）已經對整套做過事實、口吻與中英用字、深度連貫與國考的批評，事實有 2 位反駁者，修訂後複查，最後全套檢查。主 session 卻照舊計畫，在算圖後又開了完整的審查（六個面向、每個面向 2 位反駁者，31 個代理），等於把同一份內容再查一遍。真正新的證據只有 PowerPoint 實排：17 張表格溢出、標題壓字，這些只在 PNG 看得到。教師問「deepen 裡面已經有 review，為何花 token 又 review 一次」，主 session 停掉審查（已花掉 3 份審查報告與 2 位反駁者），改成一個只修版面的代理。
- **為什麼會錯**：把「交件前要審查」當成固定步驟，沒有先比對前面已經查過什麼、之後改了什麼。
- **現在怎麼做**：硬規則 16「不重複審查」。開審查前列一張表：每個面向前面哪一步查過、之後內容有沒有改；只跑有改或需要新證據的面向。階段 3 之後的審查通常只剩版面與圖片（看實排的 PNG）；內容有大改的批次才重跑該批的事實與用字。教師說：「未來做事情的時候請留意過度 review」。

## 15. OneDrive 大檔卡在 Syncing：要重開機（2026-10-16）

- **發生什麼**：10/14 晚到 10/16 凌晨，教師 Mac 上放進 OneDrive 的大檔（約 2 MB 以上的 PPTX、PDF、HTML）一直卡在 Syncing，幾乎沒有送出資料；小檔有時正常。試過改純英文檔名、開新資料夾、只重開 OneDrive，都沒用；同一台 Mac 傳 Dropbox、推 GitHub 都正常，別台電腦傳同樣的檔也正常。教師把 Mac 重開機後，OneDrive 就能上傳大檔了。
- **推測原因**：這台 Mac 的系統同步服務（File Provider）與 OneDrive 的分段上傳狀態卡死；只結束再打開 OneDrive 不會重置系統服務，重開機才會。
- **現在怎麼做**：大檔卡住時照工作區規則移出、記名，然後請教師重開機；重開機前急用就放 Dropbox 或推 git。不要再花時間試改名、壓縮或換資料夾。

## 16. check_deck 全綠，實排卻溢出：框架圖的估算錯在三處（2026-10-20）

- **發生什麼**：bone 補充小 deck（框架圖為主）gen_pptx 全綠，但這台 Mac 改用 LibreOffice＋微軟正黑體算圖（斷行與 PowerPoint 相同）後，看到粗體節點格的字超出圓角框、七行的格子字貼邊、兩行的資料來源行壓到框架圖。
- **原因**：（1）`_cell_need` 用一般字重量粗體的節點格，少估一兩行；（2）格子行距 100%，PowerPoint 實排每行 1.2×字級（量 PowerPoint for Mac 存的 headneck-dent PDF：20pt 字行距 24pt，LibreOffice 相同），`line_h` 的 1.12 是照條列（行距 110%）校正的，拿來算格子每行少 7%；（3）`L_diagram` 固定扣 0.4 in，沒扣資料來源行（一行出處只剩 0.03 in，兩行就壓到）。
- **現在怎麼做**：gen_pptx 三處都改了（kit-draft bf39ce6）。算圖後一律跑 `check_render.py <pptx> <pdf> --warn-pt 4`，它量 PDF 上每一行字實際的位置（RED：格子溢出、兩段字互壓、超出投影片）。Mac 不必等教師按 PowerPoint 的授權：`export_pdf.py` 走 LibreOffice（`setup/mac.md`）。
- **教訓**：估算器要拿實排校正，而且每一種版型（條列、表格、框架圖）要各自校正；不能拿條列的係數套到格子。

## 17. 補充統整表：字太多、吊書袋、格式單調、語調不自然（2026-10-20）

- **發生什麼**：bone 的三份補充小 deck 第一版照「深度、統整」做成每張一個大框架圖，格子裡放了研究細節（例數、試驗期別、體外、作者推測、期刊名）。教師看了說：「版面太滿 字太多了 不用這樣吊書袋」「表格格式缺乏彈性」，要我們多用 Runway，接著改口「算了不要runway了 改成只用表格就好 但表格要做得漂亮」「字要少」，最後補「語調也不夠自然」，並要 monocytoid 的介紹「gentle 因為是針對大三」。
- **現在怎麼做**：第二版每張一個表（2–4 列、2–3 欄、格子是短語、最多一句說明句），研究細節與文獻全部移到講稿，出處行每張最多兩篇；表格用新的 `<!-- tbl: style=clean／accent -->` 樣式並變化欄數與欄寬；標題直接講病名與重點，不用「推力」「煞車」「叫來、養大」這類自創說法；新概念從學生已經會的東西一步一步帶（13 張 → 8 張）。
- **教訓**：「深度、統整」（10/14）指的是內容的連貫與比較，不是把文獻細節塞上投影片；給大三的補充張，證據放講稿、投影片只放結論。語調要先讀他的原句庫與改稿對照再寫。


## 18. 加了口吻的記號，句子還是 Claude 的文法；流程圖燒成圖檔教師改不了（2026-11-12）

- **發生什麼**：牙三造血大堂課照 2026-11-08「投影片加一點點口吻」做了兩版（加 8 處、每張檢查改 32 張），做法都是在原來的句子上加「其實」、括號旁註、問了就答。教師看了第三版說：「目前的文法還是claude文法居多」「目前來講claude的語句我還是必須要修很多」；同一版的 10 張流程圖是 `draw_flow.py` 畫的 PNG，字在圖裡，他說「我不能接受」。
- **原因**：（1）撰寫與充實的代理被要求「像上課講話」，寫出來的是自己的口語：「名詞：一句口號」、擬人動詞（短命、關起來、救不了、壓得住）、比喻標題（鐵關起來、吃掉骨頭）、電報體的表格格子；口吻查核只數記號（其實、問句），沒有逐句對他的句型。指南 22 的 BUL-02、04、06、36、37 早就寫了他的句型，但沒有一條規則要求每一句都對。（2）程式畫圖是為了中英對照好排（2026-10-14），沒想到他要改字。
- **現在怎麼做**：教師偏好第 4 節 2026-11-12 兩條、硬規則 2 與 15、指南 22 BUL-39（十點，MUST）。流程圖用 `<!-- flow: -->` 畫成 PowerPoint 原生圖形（`scripts/flow_shapes.py`）。那門課第四版整套重寫（209 張裡改 183 張、323 處），依據是他同主題的舊 deck 與他親手改稿的差分，不是語氣側寫的記號清單。
- **重寫時撞到的版面問題**：他的句子比電報體長（改稿差分：他寫的行中位 31 字、我被改掉的行 19 字）。（1）表格張的標題或說明句多一行，表格就放不下：改寫後標題的行數不能比原來多（先量再寫）。（2）很滿的表格，格子多一兩個字就多一行：這種格子維持短語，在清單告訴他。（3）有圖張的條列，gen_pptx 的量字對長英文詞估得太樂觀，估得下、LibreOffice 實排卻多一行跑出投影片；`BULLET_W_K = 0.95` 校正後抓得到。（4）字改短反而溢出：文字欄的寬度是照估算挑的，字短了挑到比較窄的欄，實排又多一行。所以每一輪改字都要算圖、跑 `check_render.py`，拿改寫前那一版的 check_render 結果當基準比。
- **教訓**：口吻不是在句子上加記號，是句子本身的文法；查核要逐句對他的句型，並且拿他同主題的原句來寫。教師要改的東西（我們寫的每一個字）都要留在 PowerPoint 裡可以改的地方。

## 19. 句型對了，用字還是我們的；他親手改過的字在下一門課被改回去（2026-11-18）
- **發生什麼**：中乙後中泌尿大堂課的毛胚照 2026-11-12 的十點寫句型（整講文法改寫最後只再改 4 張），教師看了說「目前的語彙還是有點太claude味」。同一批毛胚沿用了他舊講義上的手繪圖，他說「圖的話你先重畫 然後保留一個runway指令集」。
- **原因**：（1）事實批評與修訂為了貼教科書的字面，把他自己的字換成直譯的書面字（組織球 → 大型泡沫狀的巨噬細胞；就好 → 就夠；惡性 → 一般視為惡性）。事實沒有錯，字不是他的。（2）他一個月前在同主題的定稿上親手改過的句子，沒有人列給新課的代理看：底稿用的是他的定稿，但代理分不出哪些句子是他改的、哪些是我們當時寫而他沒動的，有三處被改回我們原來的寫法。（3）我們加的「其實」，他改稿時刪過兩處，新課又加回同樣的兩處。
- **現在怎麼做**：教師偏好第 4 節 2026-11-18 兩條。同主題有前一版時，開工先做「我們交的版本 → 他的定稿」的差分，把他增刪的句子列成一張表放進課程資料夾，寫進撰寫、批評、修訂的共同指示；用字改寫用編輯清單（原字、新字、依據）套用並產出對照表，一起交給他，他可以逐條還原。圖：他的手繪先用程式重畫（圖裡不放字，標籤用 `label_shapes.py` 畫成文字方塊），另附 Runway 指令集。
- **畫圖與版面撞到的事**：每個名詞都寫中英以後，left 版型的文字欄常被擠到 57–65%，右欄只剩 2.75–3.5 吋；24pt 的中英標籤一個就 1.5–3 吋寬，放不下。先用 gen_pptx 的量字函式量那一張在各種欄寬下需要的高度，再決定圖的長寬比與標籤放哪裡；標籤多的圖改 flash，說明句超過五行圖就只剩兩吋多高。pair 版型遇到兩行標題加五行說明句，圖只剩不到兩吋高。
- **教訓**：十點管句型，管不到詞。詞要從他同主題的舊講義與親手改稿裡找，而且他改過的字是要往下一門課帶的資產；查核「對不對得到教科書」和「是不是他的字」是兩件事，前者不該用後者去換。

## 20. 轉 16:9：只改寬度產得出來，但照片會變小、手動換行會壞（2026-11-21）

- **經過**：教師 2026-11-20 明令畫幅一律 16:9。一套 4:3 的 104 張只把 `slide.width` 改成 13.333：產得出來、檢查全綠、實排警告比 4:3 少，看起來可以直接交。整套算圖逐張看才看到：正方形的顯微鏡照片在上字下圖的版型反而變小（圖受高度限制，兩邊留白）；說明句四五行的張，圖只剩兩吋多；為 4:3 欄寬加的手動換行，在新的寬度下變成一個字獨占一行、英文在詞中間折行（14 張）。另外，前一晚只看總覽圖記下的兩件事（數字卡片只占左半邊、流程圖只占中間三分之一）逐張看是誤判。
- **做法**：(1) 改寬度、重算容量表之後，整套算圖、一張一張看，不靠檢查的綠燈，也不靠縮得很小的總覽圖下結論；(2) 照片張依長寬比選版型（寬的上字下圖，正方形與直幅的左字右圖），說明句先收短；(3) 手動換行逐處重量（用 gen_pptx 的量字函式看每格每句在新寬度斷在哪裡），量出來差 0.1 吋以內的不要賭；(4) 有標籤的程式圖改白邊與 `slot_w`；(5) 左字右圖遇到直幅的圖可以開 `layout.left_fit_image`。細節在 `docs/教師偏好與決策.md` 第 4 節「畫幅一律 16:9」。
- **為什麼會這樣**：版面的估算只保證「放得下」，不保證「圖夠大、斷行好看」；這兩件事只有看實排才知道。手動換行是照當時的欄寬調的，換了畫幅就失效。

## 21. 請別的模型改句子：保守的指示它幾乎不動；整張重寫才有用，但程度詞要逐張對（2026-11-21）

- **經過**：教師要把一講的句子交給 Gemini。第一版的包只有規則與逐句原文，他說沒有研究資料會改得很糟；第二版加了研究資料，但規則是「改成像他的句子、已經像的不要動、寧可少改、新句不可以比原句長」，還附了他的舊句子當範本，Gemini 只動了很少的地方，他說「非常不行」「我是喜歡gemini的語法的」。第三版改成請它用自己的話整張重寫、每一張都要回，101 張的相似度中位數降到 0.68，他當天就把這一步列為必備流程。
- **為什麼前兩版不行**：指示的每一條都在叫對方少動、模仿；逐句回「只列有改的」表，也讓它可以幾乎不回。要對方發揮，就只鎖底線（事實、數字、名詞、版面），其餘明講交給它，並要求每一張都輸出。
- **重寫回來要看什麼**：數字、頁碼、英文、上色、表格形狀它都守得住（機械檢查 101 張全過）。守不住的是程度詞與時態：often 寫成「多」、may 寫成「容易」、many 寫成「多數」、不到一成寫成「極少」、過去的標準做法寫成現在還是。這些機械檢查查不到，要拿「改成」逐張對事實帳的原文；一講約一成的張有一兩個字要換回。它還會新用我們檢查會擋的連接詞（進而、此外、因而）與沒有帶英文的名詞。
- **不要自己動刀**：超長、漏數字的張請對方自己修（退回包）；我們只換事實用字、補英文、調排版記號。我們一改寫，那一句又變回我們的話，教師要的正好相反。
- **版面**：字數上限抓太緊它又會不敢改，所以上字下圖的張用「不比現在多行」當上限。有圖的 left 張欄窄、英文長詞多，字數在上限以內也可能多折一行（孤字各占一行）超出版面，檢查還是綠燈；套回以後一定要整講算圖逐張看。先前照舊句子調的手動換行全部作廢，要重排。
- **連帶的事**：套回以後，照舊句子寫的編輯清單（用字對照表、可重跑的修改清單）都對不上。重寫包交出去到回覆套回來之間，不能改那一講的來源檔。

## 22. 備忘稿裡的字學生看得到；教師的回答先分清楚是通則還是只管這一次（2026-11-21）

- **經過**：教師說「備忘稿全清掉 我不用那個東西 也不要讓學生看到」。備忘稿是 PowerPoint 的講者備註欄。查交件資料夾才知道範圍：有講稿檔的課，gen_pptx 把整份講稿放進每一張的備忘稿；實驗講義把截圖說明、來源，連寫給教師的內部說明都放在那裡；他自己定稿的檔也還帶著。他 2026-11-08 就說過不看講稿，我們只停了在講稿上花功夫，沒有去想那些字還跟著檔案走。
- **改了什麼**：gen_pptx、gen_lab_pptx、to_claude_slides 預設不寫備忘稿；check_deck 看到有字就 RED；`strip_notes.py` 查任何一份 PPTX、或清掉另存（直接改 zip，其他零件逐位元不變，所以他自己改過的定稿也可以清）。實驗講義原本放備忘稿的截圖說明與來源改寫到 `--src-list` 的清單。
- **學到的**：他說「不看」「不用」的東西，要回頭查它有沒有還在交出去的檔裡。檔案裡學生打得開的每一個地方（備忘稿、隱藏的張、圖的替代文字、檔案屬性）都算交出去的內容。
- **先驗再說**：我原本以為當天交的那一講也有備忘稿，差點照這個假設重產、再交一版；先量了才知道那門課沒有講稿檔、交出去的檔本來就是空的。要告訴教師「哪些檔有」以前，逐份量過再說。
- **通則還是只管這一次**：同一則訊息裡，他對那一講的三個問題回「留 不還原 不拿掉」，接著說「但不當成凡例」。這種回答只記在那門課、只放行他點頭的那幾處（`course.yaml` 的 `style_allow`），不去改規則，下一講照樣問。他沒有說範圍的時候，先看那句話是在回答某一份檔的問題，還是在講他自己的習慣（「我不用那個東西」是後者，寫成通則）。
