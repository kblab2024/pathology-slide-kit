# 中醫系講義流程：中醫師國考與融合中醫的對照

適用：中醫學系（B 班：中醫學系乙組＋學士後中醫學系合班）的病理學大堂課。規則在 `AGENTS.md` 硬規則 19（中醫系那幾句），教師原話的前後文在 `docs/教師偏好與決策.md` 第 4 節（「每一講上限 110 張…」那一條）；本檔寫做法。第一個照做的是中乙後中泌尿 L1（私人 repo `courses/uro-kidney-b2`，2026-11-22 草稿4–7），範例在第 4 節。

一講的流程照舊（`docs/SOP_新教案流程.md`、`docs/多session做法.md`），中醫系多兩件事：

1. **國考題用中醫師國考**（第 2 節）：內容定下來以後挑 15–18 題，照器官放進講義。
2. **把中醫的對照融合進原講義**（第 3 節）：三方對照（方劑與關鍵組成 → 證型 → 西醫病理）的深度研究 → 少而精的融合張與加一行 → 國考題下面那一行寫三方對照 → Gemini 融合包 → 詳細的教師手冊。

兩件事都做完、算圖看過，才出 Gemini 重寫包或融合包（硬規則 17）。

4. 看了第一版（15 題）：「改放中醫臨床醫學裡和西醫病理有關的題」「中醫師國考題庫六科全建」。
5. 「我很想知道中醫醫理上為什麼是這些答案 出處又是什麼」→ 逐題的中醫醫理與出處（第 2.5 節）。

8. 看了草稿6（3 張融合張、2 行）：「我覺得中醫融到10張試試看」「之後重產gemini融合包」「請把中醫流程跟中醫國考流程寫進main kit」。

## 2. 中醫師國考流程

### 2.1 題庫

- `question_banks/中醫師/`：考選部中醫師考試 104–115 年（每年兩次）、六科全收（教師：「中醫師國考題庫六科全建」），共 11,520 題。科號：1 中醫基礎醫學(一)、2 中醫基礎醫學(二)、3 中醫臨床醫學(一)、4 中醫臨床醫學(二)、5 中醫臨床醫學(三)、6 中醫臨床醫學(四)。
- 一場考六科、每科從第 1 題編起，所以每題有 `key`＝`{年度}-{次}-{科號}#{題號}`（例 `112-1-4#28`）；`common.load_questions` 有 `key` 就用它。
- 重建或加新年度：`scripts/build_tcm_bank.py`（抓考選部的試題、答案、更正 → 去重 → 逐科解析 → 合成一份；用法在它的 docstring）。原始 PDF 放 repo 與雲端資料夾以外；`--mask` 一定要給（有兩題提到教師服務的學校與醫院）。
- 解析不確定的題有 `parse_note`（「選項是圖」「選項可能錯開」）：要用這種題，先對原始試題 PDF。

### 2.2 挑題

- **只從中醫臨床醫學(一)～(四)（科號 3–6）挑，而且題幹或選項要有西醫的病名、檢查或手術**（例：抽菸加無痛血尿的膀胱癌、化療後的出血性膀胱炎、前列腺肥大、TURP、精液分析、AFP）。中醫基礎醫學(一)(二) 的題（內經、本草、方劑）與只有中醫概念的臨床題不放。
- **照器官或臨床表現放在教那件事的張後面**（「不會有病理題 你要用器官去關聯」）：前列腺增生配癃閉、腮腺炎併發睪丸炎配毒竄睪腹、無痛血尿配膀胱癌、陰囊水腫配水疝。找不到器官對得上的段落時，可以用病理的共通點接（例：腫瘤標記 AFP 接鼓脹的肝硬化與卵黃囊瘤），列進待教師裁決清單。
- **每講 15–18 題、各節大致平均**（硬規則 19）。同一件事有好幾題時留一題；拿掉的與沒放的候選列在參考資料（「符合條件、這一版沒有放的題」），他說題號就換。
- 每一題對一次原始試題 PDF 與答案、更正（題庫是程式解析的；舊版試卷的選項與題號偶爾錯開）。
- 粗篩可以用程式：在科號 3–6 的題幹與選項搜這一講的器官名與西醫病名，再逐題讀。L1 照這個判準找到 35 題左右，西醫內容明確的二十幾題。

### 2.3 放進講義

- `course.yaml` 的 `decks.<deck>`：`question_bank: 中醫師`、`quiz_label: "{年度}-{次} 中醫師 {科目}"`（印成「112-1 中醫師 中醫臨床醫學(二)」；`{科目}` 從題庫來）、`hours: 2`、`sections: 3`、`per_section`；放寬上限時加 `cap`（附原話）。
- 國考題張寫在 `<課程>/_archive/build/deck_moves_<deck>.json` 的 `quiz`：`[{slug, key, after, note, why, ref}]`（slug 含 `-q-`），`scripts/deck_moves.py --course <課程> --deck <deck>` 插進素材池與選單（可以重跑；素材池是從批檔組裝的課，每次組裝後都要再跑）。同一份 json 的 `move_to_ref` 是張數超過上限時移到參考資料的張。
- **題下那一行（note）**：我們的話，把題目接回這一講、附 Robbins 頁碼；融合以後寫成「方劑（關鍵組成）→ 證型 → 西醫病理」（例：「石韋散（石韋、冬葵子、瞿麥）→ 石淋（尿中夾砂石）→ 結石(calculi)卡在輸尿管(ureter)引起腎絞痛(renal colic)（Robbins p.861）」）。兩行以內；不能有 `>`（寫全形 `＞`）；中英對照照常。
- 參考資料（只給教師，硬規則 18）的國考題那一部分：每題的年次、科目、題號、答案、接在哪一張、為什麼挑這一題、沒放的候選。

### 2.4 B 班的其他規則

- 仍然不放醫師國考題（EXAM-23 的這一半照舊）。
- 中醫師國考的題是給學生看「自己學的中醫和這一張的病理怎麼接起來」，不寫考試導向的評價句。

### 2.5 逐題的中醫醫理與出處（他問了再做）

他問「中醫醫理上為什麼是這些答案 出處又是什麼」時，另寫一份 markdown 只給他：逐題的證型、治法、其他選項為什麼不對、方劑的組成與教材或古籍出處，每一點標查證的程度（古籍原文核過、國考題本身證實、教材通說沒有打開）。這一份也是第 3.2 節深度研究的輸入。

## 3. 融合流程

### 3.1 原則

- **融合進原講義、少而精、不佔正課**：不另外做一套教中醫的投影片。三種位置：融合張（`<!-- fuse: yes -->` 的對照表，不算有圖率）、原來的張加一行、國考題下面那一行。
- 每一張的主角仍是病理；融合不能拿掉或擠掉原來的內容。張數放寬只管教師放寬的那一講（L1：115 張、三節各 35 分鐘）。
- 份量：L1 草稿6 是 3 張融合張＋2 行；教師要「融到10張試試看」以後，草稿7 是融合張 5＋加一行 5。
- 融合的字是我們寫的，上課用的版本要經過 Gemini（融合包，第 3.6 節）。

### 3.2 三方對照的深度研究（`workflows/tcm-fusion-research.js`）

- 每個主題一位研究者（high）寫一節三方對照、一位查核者（xhigh）試著推翻並直接改正 → 組報告（xhigh）→ 完整性批評（high）→ 修訂（high）→ 融合對照表（xhigh）→ 融合查核（xhigh）→ 詳細的教師手冊（xhigh）。代理數＝2 × 主題數 ＋ 6。參數、DONE 表與報價見 `workflows/README.md`。
- 主題由 args 給（`clusters: [{key, title, scope}]`）：照這一講的病分（例：尿血與膀胱癌、淋證、癃閉與前列腺增生、精濁與前列腺炎、睪丸與陰囊），再加組成藥的藥理兩節、成分的安全性、方法學各一節。
- 產出（放課程 `_archive/research/<主題>_<日期>/`）：深度研究報告（只給教師念）、融合對照表 `fuse_<deck>.json`、教師手冊。開跑前照硬規則 10 空跑、報價，他說好才跑。
- **證據規則**（研究者、查核者都照）：
  - 證型是功能性的分類，不是解剖病理的分類；同病異證、異證同病是中醫自己的原則。沒有任何研究比較過不同證型病人的組織切片。
  - 每個三方對應標種類：教材或共識的對照／實證研究／機轉推論／沒有可靠對應；藥理證據標等級：人體試驗、動物、細胞、只有網路藥理學或分子對接（網路藥理學與分子對接一律只當假說）。
  - 每個主張附出處；沒有打開核對的寫「只看到摘要」「未核對」；不編造引用。
  - Robbins 沒有寫的（例：馬兜鈴酸），出處行寫明 Robbins 沒有、另引文獻。
  - 不替中醫或西醫下評價，只講證據有多少、多可靠；「沒有找到」不寫成「證明無效」。

### 3.3 挑融合的項目

- **查核過的三方對照**：證與病在症狀層次幾乎一對一的幾條最好用（石淋＝泌尿道結石、水疝的光照透明＝陰囊水腫透光、痄腮的睪丸腫痛＝青春期後的腮腺炎睪丸炎）；方劑寫關鍵組成。
- **對到證型要有依據：文獻、教材或國考**（教師 2026-11-22，兩句話接著說）：
  - 先說「我覺得你要用模型能力發揮一點想像力 想像一下有那些疾病可以對應到證型」：不要只挑方劑與安全性的證據，要把這一講的每一個病都想一遍，它在中醫會被辨成哪一證。
  - 看了照這句做的草稿7，又說「都換換 多查一些文獻 然後重做融合包 32 64 109的加一行都不對證 請拿掉」。被拿掉的是：軟化斑「像正虛邪戀，多辨成勞淋」（正虛邪戀是病機，不是證型）、BPH「肝鬱氣滯近平滑肌收縮」（證型是教材的，但對到平滑肌是我們的類比）、陰囊腫塊「紅腫熱痛屬陽證、無痛硬塊屬陰證」（八綱，不是證型）、「前列腺癌早期無證可辨」（不是證）、「前列腺炎三型各像哪一證」（類型對證型是我們想的）。
  - 所以想像是用來**找候選**（每個病都想一遍），**放上投影片的證型要有出處**：證型分布或證候要素的臨床研究、專家共識或團體標準、範圍綜述或系統性回顧、規劃教材、國考題（題目把那個證配那個方當正確敘述）。只有我們自己的類比、只有病機或八綱的，不放。
  - 怎麼查：中文關鍵字「<病名> 中医证型 分布／证候要素／辨证分型／专家共识」與英文「<disease> TCM syndrome distribution」都搜；PubMed 的網頁會擋自動讀取，用 NCBI E-utilities（`esearch.fcgi`、`efetch.fcgi?rettype=abstract`）讀摘要；中文期刊讀摘要頁或 PDF。每一篇都打開核對篇名、作者、期刊年卷頁、樣本數與數字；沒有打開的不放。
  - 寫法：西醫那一邊照常只用 Robbins（附頁碼與事實帳 id）；證型那一邊寫出處（期刊縮寫、年、卷、頁）。頻率是「文獻裡的使用頻數」還是「病人的分布」要分清楚，照作者的寫法；整張都是百分比的表他會打叉，表格寫順序、主症與方，數字留在教師手冊。不和國考題下那一行打架，不多教原講義沒有的病理。
  - L1 草稿8 的例子（每一項的文獻在範例那一節）：膀胱癌（範圍綜述：濕熱、瘀毒最多；國考 113-2：八正散、桃核承氣湯）、慢性前列腺炎（561 例調查：濕熱、血瘀最多；國考 108-2 的濕熱瘀阻＝這兩型）、間質性膀胱炎（兩篇文獻：本虛標實）、雄性素阻斷後（綜述：陰虛火旺）、BPH（尿動力學研究：腎陽虛最常見，逼尿肌收縮力弱的過半屬之）。睪丸扭轉、睪丸萎縮、隱睪、睪丸腫瘤找不到辨證的文獻，就不放。
- **安全性**（研究裡證據最硬的一塊）：含馬兜鈴酸的「木通」頂替品與上泌尿道泌尿上皮癌（台灣健保研究有劑量反應，2003 年禁用）放在講那個病理的地方；延誤診斷（無痛血尿先排除腫瘤、陰囊急痛先排除扭轉）放在教那件事的張。
- 想過、但沒有放的寫進融合對照表的 `excluded`（`fuse_prepare.py` 抄進 `deck_moves_<deck>.json` 的 `fusion_excluded`），也列進待教師裁決清單。

### 3.4 版面限制（L1 學到的）

- 融合張：標題 ≤22 字、條列 ≤2 條、表格含表頭 ≤4 列 ×≤3 欄、每格 ≤16 字（括號裡的英文另計）；slug 含 `-fuse-`。
- 加一行：≤28 字，那一張的可見字數加上這一行 ≤200（`check_deck.py` 的字元 RED）。表格或流程圖會被擠出投影片（`check_deck.py` 的表格高度 RED、`check_render.py` 的字超出投影片）、或條列已經四條擠滿文字框時，換一張教同一件事的張。
- 每一次出現的專有名詞都寫「中文(English)」（`style_check.py` 會擋；表格的類型欄也一樣）。中醫的字不用「中醫」當主詞（`style_check.py` TCM-26），寫方證名、證名或「屬陰證」這類說法。
- 左字右圖的張欄窄：用 `⏎` 在詞與詞之間換行，免得證名、「先想」這類詞被拆在兩行。
- 新的張與加了一行的張，算圖逐張看。

### 3.5 程式

```bash
cd "<kit>/scripts"
SLIDEKIT_MATERIALS="<materials>" PYTHONIOENCODING=utf-8 python fuse_prepare.py --course <課程> --deck <deck> <fuse_<deck>.json> [--max-slides 5] [--max-inline 5] [--notes]
SLIDEKIT_MATERIALS="<materials>" PYTHONIOENCODING=utf-8 python deck_moves.py --course <課程> --deck <deck>
# 之後照常 gen_pptx.py、style_check.py、export_pdf.py、check_render.py
```

- `fuse_prepare.py`：融合張寫 `<課程>/_archive/written/w_fuse_<deck>.md`（已經有的張保留，主 session 為版面精簡過或 Gemini 套回過的字不會被蓋掉；json 寫 `"replace": true` 才換）、加一行寫進 `course.yaml` `rewrite.src` 列的批檔、國考題說明寫進 `deck_moves_<deck>.json`、融合包設定寫 `<課程>/_archive/revoice/fuse_pack_<deck>.json`；`--notes` 另寫參考資料的融合那一節（`_archive/build/fuse_notes_<deck>.md`，張號讀成品的 `_layout.json`）。
- `course.yaml`：`rewrite.src` 要列 `_archive/written/w_fuse_<deck>.md`；放寬的上限寫 `decks.<deck>.cap`（附原話），`check_deck.py` 照它查；融合張不算有圖率。
- 加一行放錯張要搬：從批檔拿掉那一行、從 `deck_moves_<deck>.json` 的 `fuse_inline` 拿掉那一筆，改 json 的 slug 再跑 `fuse_prepare.py`。

### 3.6 Gemini 融合包

- `rewrite_pack.py make --course <課程> --deck <deck> --out <repo 與雲端資料夾以外> --fuse <課程>/_archive/revoice/fuse_pack_<deck>.json`：整講一份，只包融合張、加一行的張與國考題說明（`scripts/README.md`「融合包」）。和草稿一起交，交件檔名 `給Gemini_融合包_<講題>_草稿N.md`、`0_怎麼用_融合包_<講題>_草稿N.md`。
- 重產融合包時，待教師裁決清單寫明前一版的融合包作廢、不用帶回來。
- 交出去以後、回覆套回來以前，不改那一講的批檔與 `w_fuse_<deck>.md`。
- 回覆回來：`rewrite_pack.py apply`（機械檢查；Q 行另外寫 `_archive/revoice/rewrite_<tag>_<deck>_quiz.json`）→ 逐張對事實（素材在融合對照表）→ 套回 → Q 行套回 `deck_moves_<deck>.json` 的 `quiz[].note`（kit 還沒有這支程式，第一次套用的課寫好後收進 kit）→ 重產、算圖 → 下一版。條列裡的 `⏎` Gemini 不會寫，套回後照算圖再加。

### 3.7 教師手冊（要詳細）與交件

- 教師手冊（只給他）：總覽（證型和病理是兩套軸、這一講融合了哪些放在哪裡、每節時間怎麼分、哪些能當事實講哪些只能當假說講、一定要講的安全性），逐張（每張融合張、加一行、每一題國考題：中醫醫理、方義與組成、病理、證據等級與講法、不要說的），附錄（沒放但他可能想補的、還不確定的事）。融合的項目換了或加了，手冊補一節再交新版（L1 草稿7 補了「新加的 5 項」）。
- 待教師裁決清單最上面一節：這一版融合了什麼（張號）、每一項的依據（文獻或國考的出處）、版面怎麼調、請他決定的事（要不要換、份量、各節張數、跑不跑融合包）。
- 一起交：PPTX、PDF、HTML、HTML小圖、待教師裁決清單、參考資料（含融合那一節）、待補圖清單、教師手冊、融合包與怎麼用；深度研究報告第一次交，沒有改就不重交。交件管道與檔名照 `docs/教師偏好與決策.md` 第 8 節與工作區 `AGENTS.md`。
