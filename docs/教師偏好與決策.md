# 教師偏好與決策

這份文件把原本只存在本機記憶檔與舊專案 CLAUDE.md 裡、需要長期記住的事整理出來，讓雲端 session 與其他工具的代理也讀得到；教師的偏好與裁決以本檔為正本，其他檔只寫一行指過來。投影片風格的細節（字級、密度、用語、國考題格式）以 `style/guide/` 為準，但第 4 節有日期、適用所有課的裁決高於指南。本檔寫「他是怎樣的老師、他怎麼做決定、我們怎麼跟他合作」。

## 1. 他是誰

- 授課教師是教學醫院病理部醫師，教醫學系、中醫系、牙醫系的病理學大堂課與實驗課，也做國考複習課。封面作者欄寫他的本名（公開版不列）。
- 他就是這兩個 repo 的使用者：對代理（Claude 或其他工具）下指令、做裁決的是他本人。

## 2. 教學理念

- **原話：「聽課應該是要回去知道怎麼唸書，不是唸書給你聽。」** 課是給學生讀書的框架，不是把教科書念一遍。
- **框架靠「功能推組織」的一句話推論**，不靠貫穿全套的比喻或金句。他親手寫的是「走食物的路需要耐磨，因此組織學上是鱗狀上皮」這種一句到位、落在組織學或機轉的推論；我們寫的長比喻與金句標題，他會削成名詞（例：一句「唾液腺是這張長在裡面的皮膚的汗腺」被他改成「唾液腺」）。
- **對考試現實直說**（「不調分、不加分，考幾分就是幾分」），**對教科書有態度**（「Robbins因篇幅限制就此打住 想知道更多只能看這篇」）。這種語氣是他本人的，可以照寫；我們自己加的戲劇化語氣不行。
- **不把時間上滿。** immune 一節排約 60 張、以 40 分鐘講完為目標；同標題連張與純圖張走得快。
- **學生要看的東西放在投影片上。** 備註可短可空，他不讀也不改我們寫的備註。

## 3. 誰說了算（權威順序）

1. **事實**：Robbins & Cotran 11e 是唯一正典。他會用更新的文獻覆蓋 Robbins，但一定在句內附出處（例：口咽癌 HPV 比例用 2025 年的文獻改成七成）。我們不自行覆蓋；Robbins、文獻、他的舊投影片衝突時，選一個做法做進成品並列清單請他裁決。
2. **風格**：他親手改我們的稿 ＞ 他自製的 2026 ＞ 2025 ＞ 2024 ＞ 他對某一門課的明令（只管那門課）＞ 我們的毛胚（只當反例）＞ 他人的投影片（只當對照）。細節見 `style/guide/01_權威順序.md`。
3. **他沒動到的不算他同意。** 他改稿常只改到前半、或只改他注意到的那一張；殘留下來的我們的寫法只算「容忍」。
4. **某門課的明令不外推。** immune 的「標題 36、內文 28、學生要讀的字 ≥20、出處 14、牙醫師國考題」只管 immune。（每張專有名詞中英對照原本也是 immune 的明令，2026-10-14 他擴大到所有課，見第 4 節。）
5. **這份文件、風格指南、各課 brief.md 與舊記憶不一致時**：第 4 節有日期、適用所有課的裁決最優先（指南還沒改到的地方以它為準）；其餘風格以指南為準；課程規格以該課 brief.md（有日期的裁決表）為準；同一件事有兩個有日期的裁決時，新的蓋過舊的。舊記憶與 repo 不一致時以 repo 為準。

## 4. 他怎麼做決定、怎麼改稿

- **裁決短而明確，常一次給完。** immune 開工時一次裁了張數、節奏、國考題、正常免疫的份量、正典、字級與中英對照；呼吸系統課一次給了五個裁決。每一條都要連日期寫進該課 `brief.md` 的「教師已裁決」表。
- **範圍會在過程中調整。** 呼吸系統課中途補了漏列的血管性疾病、把組織學縮減讓給「愛考的」肋膜。調整後要同步改 brief.md、course.yaml 與藍圖。
- **別章教的不展開。** 他在別的課教過的主題（例：結核免疫、真菌形態、非血栓性栓塞）只做「見第 N 章」式對照，國考題也不選要靠別章才能答的。
- **他有自信的段落自己做。** 例：呼吸系統的「腫瘤發生與化生」他說要自己重做，我們先用文獻頂著。
- **缺圖他自己補。** 不畫佔位框、不做「圖片待補」張；給他一份待補圖清單。
- **改稿的習慣**：順著投影片往下改；刪張、補圖（組織圖、期刊圖、Robbins 圖）、把標題改成完整陳述句或純名詞；字級幾乎不動；備註不看。
- **換班時沿用底稿、只刪不寫**：改封面講題、改簡介的班級事實、刪醫師國考題、刪或搬整段、清掉失效的目錄張（`38_課別差異.md` AUD-01）。
- **專有名詞一律中英對照，每一張都寫（2026-10-14 明令，他要求寫進所有主文件）**：他看到一張只有中文的程式機轉圖時說「這種東西的名詞沒有中英對照是很危險的」「寧可多花一點張數，也要把中英對照做好」「所有內容都一樣」。所以：
  - 投影片文字、圖上的標籤、表格、流程圖、程式畫的圖、AI 重繪圖的標籤，每一張的專有名詞都寫「中文(English)」（course.yaml `bilingual: per_slide`）。
  - 有中文名的縮寫（PSA、DHT、MRI…）也寫中文，寫成「中文(English; 縮寫)」；`bilingual_whitelist` 只留沒有中文名的基因符號、染色簡稱、機構名。
  - 放不下就拆張或換版型，不准為了省空間拿掉英文；張數因此變多可以。
  - 國考題張照題庫逐字，不在此限。
  - 所有課程都照這條，新課程不再用 `first_per_deck` 當預設。
- **示意圖的標準做法（2026-10-14 明令，他說「字最清晰」）**：影像模型（Runway 的 GPT Image 2.5 Sunburst 等）只產**沒有任何字的母圖**；標籤由做投影片的代理設計（放在哪個白邊、引線拉到哪個構造、每個標籤兩行「中文」「(English)」、標題一行「中文(English)」），用 `scripts/label_image.py` 以微軟正黑體疊上，放到投影片上至少 24pt。不讓影像模型寫字，也不用「叫 Runway 加標籤」的 prompt（headneck-dent 試過：模型寫的字會糊、會錯字；先出母圖再由代理加字的版本最清楚）。
  - 標籤的規格檔（JSON）留在課程的 `_archive/runway/labels/`，改字或移位置只要改規格重跑；母圖原檔不動。
  - 給 Runway 的 prompt 結尾一律寫 "No text, no labels."，構圖要留白邊給標籤。
- **不要單句張；內容要有深度、統整、連貫（2026-10-14 晚，看完 uro-a3 的 110 張毛胚）**：「我覺得大架構很不錯 但是因為為了你被我某些大字slide影響誤以為字都很大的關係 深度跟統整性是略顯不足的」「我覺得大字報不用那麼多(不要低於24就好)」「24-35 不用拘泥一定要24」「可以在120以內多充實一些內容 且增加連貫性」「版面因此就可以比我的原檔精緻很多」「please suppress one-sentence slide (it was only thing that i started to dislike in my old slides, while other styles im quite proud with)」。所以：
  - 他舊 deck 的單句大字張不是他的偏好，是他唯一不喜歡的舊風格；每張內容張要有一個以上的重點（說法＋解釋、機轉、比較、例子或考點），封面、分隔張、國考題張除外；只有一行圖說的圖片張也要補讀圖重點。
  - 內文 24–35pt 依版型選，不必都壓到 24；表格與標籤 24；只有出處行可以更小。
  - 適用範圍（2026-10-14 整理文件時的預設，待他確認）：新做的大堂課 deck。已交件、有自己字級明令的課（immune、headneck-dent：學生要讀的字 ≥20）重產時照該課明令，要不要改成 24–35 先問他；實驗講義照他自製的實驗講義版型（`gen_lab_pptx.py` 的 20.2pt 說明句）。
  - 照 Robbins 補深度，加比較表、分類表等統整，加段與段之間的銜接與回扣；版面用 kit 的表格、左右並排、圖文組合，做得比他的原檔精緻。
  - 他其他的風格（句子、口語、=>、「不是 X，而是 Y」、!!常考題、橘藍強調、考試導向）他很滿意，照留。
- **他的錯字照留**（例：白班／紅班、cilitated、Sjogren），規則見 `24_術語與中英對照.md` TERM-18；**事實錯誤要列清單請他裁決**，不靜默沿用也不靜默改。

## 5. 他對代理工作方式的要求（Claude 與其他工具都一樣）

- **所有代理一律用 Opus**（2026-09-24 起的決定，不換其他模型；反駁與複查也一樣）。寫工作流時每個 `agent()` 都帶 `model: 'opus'`（`AGENTS.md` 硬規則 8）。用其他公司的工具時怎麼選模型，照硬規則 8（2026-10-14 整理文件時寫的做法，他沒有另外裁決）。
- **每個代理明寫強度**（2026-10-14 起）：不寫 effort 會繼承主 session 當時的強度（那天 uro-a3 撰寫第一次開跑就繼承到 medium），不是「預設的最高設定」。各角色用哪一級照 `workflows/README.md`「角色與強度」。
- **建一套課分四個階段、四個 session**（2026-10-14 晚，看完 uro-a3 的結果）：「i think this build script and tool => research with ultracode => draft with high/extra => deepen with ultracode workflow is surprisingly effective and economic, maybe record in all repos and local memories」「stage 0 1 2 3 totally 4 session」。
  - 他原本以為 uro-a3 的初稿是用「high」跑的；查紀錄是 xhigh 30 個、max 27 個代理。他選「照實記 xhigh＋查證用 max」，多輪結構保留（21:42）。
  - 研究也和他的說法不同：uro-a3 的研究是 kit 的標準結構、62 個代理全部 xhigh（繼承 session），沒有 max 與複查。分配表在研究階段用 max 的部分還沒實測，第一次照表跑時報價要和 uro-a3 的研究對照（`docs/多session做法.md`）。
  - 接著主 session 提出各角色用 max／xhigh／high 的分配表（21:44）與反駁與複查的四條上限（21:48），請他決定；他 21:52 回「請把這些都整理進所有repo與slidekit記憶 並且完全統整這些專案的說明 讓未來的任何agent包含其它公司的工具都可以歡喜奉行」，視為採用（他沒有說「採用」兩個字，之後也沒有反對）。四條上限是照他 21:48 說的事提的：之前費用失控最嚴重的那門課（lung），錢幾乎都花在用比 opus 更貴的型號跑的多輪反駁（原話含舊型號名，不寫進 repo）。
  - 做法見 `docs/多session做法.md`；分配表與上限見 `workflows/README.md`、`AGENTS.md` 硬規則 16。
- **沒有額度時不要自動續跑長工作流。** 停在一個階段的邊界、記錄進度（DONE 表）、告訴他停在哪裡，等他說可以再繼續。代理回傳 null 就中止，不重試。
- **已完成的代理不重跑**：續跑一律用 DONE 標籤表。
- **開跑工作流前的固定步驟**（2026-10 起）：照 `docs/多session做法.md`「一個 session 的流程」第 4–5 步：更新 handoff、壓縮對話、確認筆電不闔蓋帶出門、空跑後照代理數上限報代理數、強度、費用與時間並附目前用量，他說好才跑；會開 PowerPoint、會跳 macOS 授權視窗的步驟，等他在電腦前再做（他不在家時按不了允許）。
- **常用程式與偏好推到所有 repo**（2026-10-14：「一些常用 script 跟喜好可以更新到所有 repo，並且 commit push merge」）：
  - 在兩門課以上用到的程式，收進 kit 的 `scripts/` 或 `workflows/tools/`；課程只留設定檔。
  - 他的新偏好寫進 kit 的文件（本檔、`AGENTS.md`、指南、範本）與私人 repo（課程的 brief、CLAUDE.md、handoff）；各工具的本機記憶放摘要、repo 不能放的原話與指向。
  - commit 並 push 到工作分支不必問；開 PR、合併進 main、直接推 main 照他當次的指示，沒有指示先問；kit 的工作版同步到公開版是他 2026-10-14 已說好的。
- **大工作做完要把可重用的東西整理下來。** immune 完成後他要求接著寫完整的風格指南；之後的課也一樣，把新學到的寫進指南、SOP、lessons_learned。
- **他事先授權過的下一步可以直接做**（例：「藍圖與風格挖掘跑完直接開始撰寫」），授權只限那一次；新的大動作（新工作流、搬檔重整）先問。
- **問題集中問、不零碎問**：開工前一次問完；做的過程中遇到要他決定的，先照預設做、記進待教師裁決清單。
- **額度與費用**：用 Claude 時：雲端 session 先扣雲端 session 額度（2026-09 送的一次性額度，會過期），用完改吃方案用量；他買的 usage credits 開關保持關閉，不要建議他打開；每個工作流開跑前先空跑，照代理數上限報 API 牌價換算的估計金額（見 `docs/cloud_session_教學.md` 第 9 節）。用其他公司的工具時怎麼報，見 `docs/跨工具做法.md` 第 7 節。

## 6. 課程代碼

檔名與封面用課程代碼，不寫系名。病理小組配當表（102–115 學年）的對照：

| 代碼 | 班別 | 國考題 |
|---|---|---|
| A1～A4 | 醫學系與中醫甲合班 | 醫師國考，每講 0–7 題，就近放在所考內容後 1–2 張 |
| B1、B2 | 中醫乙與學士後中醫合班（同一批學生先上 B1、升一年上 B2） | 不放醫師國考題；找得到對應時可放一題中醫臨床題 |
| C | 牙醫系三年級 | immune 明令放牙醫師國考（牙醫學(二)）題；C 班其他講題先問 |
| 國考複習 | 檔名「病理學國考複習_{講題}{年}」 | 題目為主體 |
| 實驗課 | 檔名寫那批學生的大堂課碼（例：病理學實驗_B1_…） | 依班別 |

「大堂課碼 C」與「實驗課碼 C」是兩套不同的碼，不要從字母推班別，查配當表。代碼對照有疑問時開工前問他。

## 7. 開新 deck 前要問他的事

完整清單與沒回覆時的預設在 `style/guide/50_檢查/51_撰寫前檢查清單.md` A 段，SOP 第 0 步有摘要。最常被漏問、做完才整套改的是：國考題的版式與正解顏色、出處寫在哪裡、關鍵字色。

指南整理出、會擋住下一份 deck 的一般性問題（至 2026-09-25 尚未得到他的回覆）：

1. 新系列用 4:3 還是 16:9？（沒回覆：沿用該系列既有畫幅，新系列 4:3）
2. 關鍵字色與國考正解色：主題橘 ED7D31，還是深藍 143F9C？
3. 文獻出處寫在句內或標題括號，還是保留管線左下「資料來源：」列？
4. 國考題用甲式表還是乙式（兩種 gen_pptx 都做得出來：course.yaml `decks.<deck>.quiz_style: 甲｜乙`）；題下要不要一行「Robbins 頁碼：判語」說明，或改接 Robbins 原文頁？
5. Robbins 表格用表格圖，還是在要求「學生要讀的字 ≥20」的課改成原生表格？
6. 他改稿時沒刪的我們的寫法，是同意還是沒時間改？

## 8. 交付慣例

- **檔名**：`病理學{碼}_{講題}(PPTX)_{YYYYMMDD}.pptx`，PDF 同名改 `(PDF)`；日期用上課日。國考複習、實驗課的檔名格式見 `38_課別差異.md` AUD-05。
- **封面**：「病理學：講題」，不寫系名、不署名、不寫第幾講；借同事的圖在封面主標下加一行致謝。
- **一檔可涵蓋多節**（immune 一檔三節）；他有時把每節存成獨立檔（`gen_pptx.py --section N`，檔名自動加「_第N節」）。
- **不放頁碼**（靜態頁碼插刪後會跳號）；不做學習目標、大綱、總結、謝謝張；投影片停在最後一個內容張或該段的國考題。
- **一起交的檔**：PPTX、PDF、`待教師裁決清單.md`（每項已選好做法並做進成品，他只要回「同意／改成…／刪」）、`待補圖清單.md`。清單最前面列「上課前最好先回」的少數幾項。
- **成品要有 HTML 版**（2026-10-14 晚：「所以其實就是成品要有 html 版，去哪裡都好做事」）。用 kit 的 `scripts/to_claude_slides.py` 從素材池產生，不手寫；目前要在有 Artifact 功能的 claude.ai 對話上傳圖片才能完成，不靠上傳的單檔模式還沒做（做之前先問他）。PPTX 仍是主檔；網頁上改的內容不會自動回素材池，回灌照 SOP 第 11 步。
- 他可以直接改 PPTX 回給我們；我們用 `dump_pptx.py`＋`diff_decks.py` 比對後回灌來源檔（SOP 第 11 步），絕不在回灌前重產蓋掉他的版本。
- **交給他的一律是草稿。** 他會自己修過才上課，不會把 AI 產的投影片或講義原封不動拿去用（2026-10-04 指示）。所以交件資料夾名稱加「草稿」（例：`<交件目錄>/牙醫系草稿/`），交件時每個檔名結尾加 `_草稿`（例：`病理學C_頭頸部疾病(PPTX)_20261012_草稿.pptx`；repo 裡的檔名不變，產檔程式靠固定檔名），講義、清單等文件標題結尾加「（草稿）」；回報時也說「草稿」，不說「定稿」或「可以直接上」。投影片畫面（封面、內容張）不加「草稿」字樣，除非他要求。
- **放進他的雲端同步資料夾（OneDrive；之後也可能用 Dropbox）**：只在他的 Mac 上做，步驟與禁用檔名在那台 Mac 的工作區 `AGENTS.md`「寫檔進 OneDrive」；讀不到那份檔的環境（雲端 session、別台電腦）不要寫進 OneDrive。原則：先確認 PowerPoint 和預覽程式沒有開著要交的檔（PowerPoint 沒有開任何簡報時才可以替他結束）；先在 OneDrive 外做好、驗好，再用最終檔名一次複製進去（2026-10-09 用暫用檔名寫入再改名，讓 OneDrive 空轉、寫入約 34 GB）；放完逐檔 `cmp`，並確認真的傳上去了（不只看 isUploaded，也看同步標記）。OneDrive 裡不改名、不覆寫，也不刪了再用同名重建（2026-10 曾因此無限重試）。
- **新版本一律用新檔名**：版次照他的叫法（`_草稿`，第二版 `_草稿2`）；同一版要再放一次就加日期時間（例 `…_20261014-2015_草稿.pptx`）。出過問題、刪掉的檔名永遠不再用。
- **大檔傳不上去時改推 git**（2026-10-14 晚：8.9–21 MB 的 PPTX 在 OneDrive 一直卡住，同時段的小 md、docx 正常；他說「還不如推到git」）：整套 PPTX 用 `git add -f` 推到私人 repo 的課程分支，他從 GitHub 下載（指令見 SOP 第 10 步）。他也說 Dropbox 可以，資料夾還沒定；定了寫進他那台 Mac 的工作區 `AGENTS.md`（本機路徑不進 kit）。
