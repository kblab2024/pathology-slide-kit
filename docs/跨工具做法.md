# 跨工具做法：沒有 Claude Code 時怎麼跑工作流

給沒有 Claude Code 的工具（OpenAI Codex、Cursor、GitHub Copilot、Gemini CLI 等）與人。規則在 `AGENTS.md`（硬規則、第 4.0 節的三種做法與強度對照），這裡只寫做法。各工具的設定名稱與指令是 2026-10 查的；各工具改版快，以各工具當時的文件為準。

## 1. 三種做法的細節

三種做法產出的檔相同。

1. **有 Claude Code 的 Workflow 工具**：直接跑 `workflows/*.js`（呼叫方式見 `CLAUDE.md`）。
2. **能派子代理、但沒有 Workflow 工具**（例：Codex、Cursor、Copilot、Gemini CLI 的子代理或背景代理；實際能力以各工具的文件為準）：照 `.js` 的順序與平行關係，一個角色派一個子代理，把展開後的 prompt（第 2 節）整段交給它，強度照 `AGENTS.md` 第 4.0 節的表設。
3. **不能派子代理**：每個角色開一個新對話或新 session 做，開頭讀 handoff 與該角色的任務，強度在開對話時照表設；主對話只排順序、記 DONE 表（第 3 節）、彙整結果。工具不能逐對話設定強度時，整段用這一階段最高的一級（查證角色不降級），寫進報價與交付說明。

不要在同一個對話裡依序做完一整個階段的幾十個角色：context 會用完，也違反「換一雙眼睛」（`AGENTS.md` 第 4.0 節）。

階段 0 交出下一階段的角色表：角色、label、順序與哪些可以同時做、強度、讀什麼、寫哪個檔。寫在 handoff 的「下一步」；列數就是代理數上限（硬規則 10）。拿不到私人 repo 的 uro-*.js 時，照 `docs/多session做法.md`「四個階段」與 `workflows/README.md`「角色與強度」排出同樣的結構。

## 2. 怎麼讀 `workflows/*.js`

檔頭由 args 算出的常數：

| 常數 | 值 |
|---|---|
| `KIT` | args.kit |
| `MAT` | args.materials |
| `C` | args.course |
| `CD` | `<MAT>/courses/<C>` |
| `G` | `<KIT>/style/guide` |
| `RUN` | `cd "<KIT>/scripts" && SLIDEKIT_MATERIALS="<MAT>" PYTHONIOENCODING=utf-8 python` |
| `ENV` | 說明執行環境的那一段文字（kit、materials、課程資料夾在哪，指令怎麼下） |

其他常數（`OUT`、`BP`、`DECK` 等）看檔頭的定義。

- prompt 是 JS 樣板字串，`${…}` 換成上面的值；有些段落由批次資料（例：`batches.json` 的一批）或前一步的回傳值組成。
- `agent(prompt, {label, phase, schema, model, effort})`＝一個角色。腳本多半包一層（例 `A(prompt, opts)`），在裡面補上 `model`、`effort` 並查 DONE 表。
- `parallel([...])` 裡的角色可以同時做。
- `pipeline(項目, 步驟 1, 步驟 2, …)`＝每個項目依序過那幾步，項目之間可以同時。
- `phase(…)` 只是分段名稱。
- `label` 是 DONE 表的鍵；`schema` 是該角色最後回報的 JSON（多半是 `{path, count, notes}`）；`A0.done` 裡已有的 label 直接沿用舊檔，不再做。
- prompt 裡的 Bash tool、Read tool、WebSearch、WebFetch 是 Claude Code 的工具名；其他工具用自己的 shell、讀檔、搜尋、抓網頁功能。
- 要看圖的角色（對教科書頁圖查核、版面 PNG 與圖片審查、藍圖讀頁圖）只交給能讀圖片檔的工具或模型。要連外網的角色（文獻搜尋、PubMed 查核、找授權圖、國考下載）先確認沙箱允許連網。做不到就不要派這個角色，寫進 handoff 的待辦交給做得到的工具，不憑文字猜。
- 之後 `wf_check_mac.js`、`check_workflows.js` 會加 `--dump-prompts`，把每個角色展開後的 prompt 各寫成一檔（待辦；做好後改這一節）。

## 3. DONE 表與停下來

- 每做完一個角色，把 `"<label>": "<輸出檔路徑>"` 加進 `<課程資料夾>/_archive/journals/<工作流>-done_<日期>.json`（格式同 `args.done`；label 用 `.js` 裡同一個字串）。
- 換工具（例：Codex 做一半、改由 Claude Code 接）時，這個檔直接當 `args.done` 用。
- 沒有 journal 就在 handoff 寫「沒有 journal，DONE 表手寫」。
- 子代理失敗、沒寫出輸出檔、工具回報額度或速率限制，都照「代理回傳 null」處理：停止派新角色、存 DONE 表、告訴使用者停在哪裡（硬規則 10）。

## 4. 強度在各工具哪裡設

max、xhigh、high 各對到哪個值，只寫在 `AGENTS.md` 第 4.0 節的表（改值只改那裡）。對照是依名次對，不是依 token 數對（各家同名的等級強度不同）；做不到就用最接近的一級，並在交付說明寫出實際設定。沒有強度設定的工具，選它主力的推理模型（硬規則 8）。

2026-10-14 查各家文件時的等級：Claude 有 low、medium、high、xhigh、max；OpenAI 依模型有 none、minimal、low、medium、high、xhigh；Gemini 3 用 `thinking_level`，有 low、medium、high（Flash 另有 minimal）；Gemini 2.5 用 `thinkingBudget`（token 數）。

| 工具 | 在哪裡設 |
|---|---|
| OpenAI | Codex CLI：`-c model_reasoning_effort=<值>`，或 `~/.codex/config.toml` 的 `model_reasoning_effort` |
| Gemini 3 | API 的 `thinking_level`；Gemini CLI 沒有逐代理的設定時用模型預設（Gemini 3 的文件寫預設 thinking 是 high，用之前再查一次） |
| Gemini 2.5 | API 的 `thinkingBudget`：max 設到該模型上限；xhigh、high 用較低的預算（沒有固定對照，交付說明寫出實際值） |
| Cursor、GitHub Copilot | 在模型選單選主力模型的推理（thinking）版本；不能逐角色設定時，照第 1 節第 3 種做法的規則 |

## 5. 對話指令對照

| 要做的事 | Claude Code | Codex CLI | Gemini CLI |
|---|---|---|---|
| 壓縮對話 | `/compact` | `/compact` | `/compress` |
| 看目前用量 | `/usage` | `/status` | `/stats` |
| 加資料夾 | `/add-dir` | 啟動時 `--add-dir` | `/directory add`，或啟動時 `--include-directories` |
| 確認守則已載入 | `/memory` | | `/memory show` |

沒有對應指令就開新對話、先讀 handoff；拿不到用量就在報價寫「拿不到目前用量」。

## 6. 其他公司的雲端代理

Copilot coding agent、Codex cloud、Cursor background agent 等多半只看得到一個 repo。

- 在 kit 上只改程式與文件，不做課。
- 環境設定腳本用 `bash setup/cloud-setup.sh`（Copilot 要 repo 擁有者另加 `.github/workflows/copilot-setup-steps.yml`）。
- `check_public.py` 印出找不到 `pseudonyms.tsv` 時，第三人真名沒查（硬規則 12）：PR 說明寫明，等維護者在兩個 repo 都在的環境再跑一次才合併。
- 在私人 repo 上看不到 kit，就不能跑工具與工作流。
- 第一次用某家公司的工具或雲端代理處理私人 repo 的內容之前，先問教師（私人 repo 的 `AGENTS.md` 規則 1）。

## 7. 報價

- 報代理數上限（與怎麼數的）、每個角色的強度、用的模型與設定。
- 費用照該工具的計價（訂閱額度或 API 牌價）估；估不出就寫「無法估」，並附 `workflows/README.md` 的 uro-a3 代理數與 token 量當參考。
- 教師說好才跑，和用 Claude 時一樣。

## 8. 換工具

- 在階段的邊界換（硬規則 8）。
- handoff 寫明這個階段用了什麼工具、模型與設定。
- DONE 表照第 3 節，接手的工具可以直接用。
