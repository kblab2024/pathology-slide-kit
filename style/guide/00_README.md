# 授課教師投影片風格指南（入口）

## 摘要

這份指南寫給「要替授課教師做病理學投影片的 LLM」，目標是交出去的 deck 他只需要少量修改。內容由 39 份投影片語料（他自製 31 檔、他親手改我的稿 3 套、我的毛胚 3 套、他人 2 檔，另加他檔內的同事甲舊張段）逐張傾印、22 個面向各一輪挖掘與兩輪反駁後寫成，另收 2026-09 課程 C（immune，牙醫系三年級免疫疾病）這份最新 deck 的教師明令與兩輪審查教訓。全指南 23 個主題檔共 843 條規則，另有本入口、01_權威順序（8 條 AUTH 規則）、兩份檢查清單與證據索引；機器可讀的規則在 style/rules.yaml（77 條文字規則給 style_check.py 與 check_written.py，76 條位置與格式檢查給 check_deck.py 或待寫的腳本）。他的風格簡單說就是：**一張講一件事，字少、圖大，用上課講話的句子，術語寫「中文(English)」，同一件事分幾張同標題的連張慢慢揭露，不寫 LLM 套語，不做收尾張，學生要看的東西放在投影片上。** 規則衝突時先看 01_權威順序。

## 讀法（依任務）

每個任務先讀 01_權威順序.md（誰說了算、哪些舊說法已被推翻），再依下表順序讀。每個主題檔的「規則」依強度排序，時間不夠時讀每檔前 5 條與「常見錯誤」。

### 任務 A：從零做一份新 deck（新課程、新班別）
1. 50_檢查/51_撰寫前檢查清單.md：開工前要問他的事，沒回覆時的預設；把明令寫進 course.yaml 與 brief.md（38 AUD-34）。
2. 30_結構/38_課別差異.md：這班考哪一種國考、有沒有底稿可沿用、張數。
3. 10_版面：11 畫幅 → 12 字級 → 13 密度 → 15 圖片 → 14 色彩 → 16 出處。
4. 20_文字：21 標題 → 22 條列 → 24 術語 → 23 禁用語 → 25 符號 → 26 語氣。
5. 30_結構：31 開場與結尾 → 32 段落節奏 → 33 divider → 34 國考題 → 35 中醫與古籍（中醫班或簡介、發炎、細胞傷害才需要）→ 36 備註 → 37 刪張與留張。
6. 40_範例：41 他的原句庫（仿句型）、43 反例庫（我常犯的錯），32 附錄 A 的三段逐張示範。
7. 一門課的撰寫 brief 範本：私人 repo 的 `style_evidence/writer_brief_immune.md`（課程 C 專用，字級與中英規則是該課明令，不外推）；新課程怎麼產生自己的 brief，見 `workflows/README.md`「新課程的撰寫 brief」。
8. 交付前：50_檢查/52_交付前檢查清單.md。

### 任務 B：在他的 deck 上改版、加張，或衍生給另一班
1. 38 AUD-01（換班只用五個動作）、AUD-03（保留的內容張逐字不改）、AUD-31（清殘留）。
2. 41 QUOTE-39（搬他的句子逐字沿用）、24 TERM-18（他的錯字怎麼處理）。
3. 12 SIZE-11（沿用 deck 的字級階層）、33 DIV-22、37 CUT-23。
4. 34 國考題的班別差異（EXAM-01、EXAM-14、EXAM-23、EXAM-40）。
5. 交付前：52，並附待教師裁決清單（38 AUD-36）。

### 任務 C：回灌他親手改過的稿
1. 42_改稿前後對照.md：EDIT-42（先比對、配對、回灌，再重產）、EDIT-34（他沒改不等於接受）、EDIT-11（事實核對）。
2. 37 CUT-30（他的張一律保留，殘留與事實錯誤列清單）、24 TERM-18、36 備註（他不讀也不改備註）。
3. 本檔「版本與更新規則」：把新證據放進語料與指南。

### 任務 D：檢查一份 deck
1. 50_檢查/52_交付前檢查清單.md（逐項有腳本與規則 ID）。
2. style/rules.yaml 的檔頭（等級對應、v0 舊 id、other_checks 的執行者）。
3. 23 BAN-30 與 S15（檢查器要跳過國考原文、以唯一句計數）、26 TONE-35（語氣類 FAIL 清單只有五類）、25 SYM-31（檢查前的前處理）、25 SYM-15（半形空格停頓不得判錯）。
4. 43_反例庫（最常漏網的寫法）。

### 任務 E：只寫一張、改一句或補一個標題
41 原句庫找同類句 → 21 標題、22 條列 → 23 禁用語 → 24 術語 → 43 反例庫對照一次。

### 任務 F：寫或改檢查器、重產 rules.yaml
本檔「規則格式說明」→ style/rules.yaml 檔頭 → 23 S13（v0 對照）、S15（檢查器等級總表）→ 26 TONE-35 → 23 BAN-30 → 各條的「機械檢查」欄。

## 適用範圍

- **適用**：授課教師的病理學投影片：大堂課（A1–A4 醫學系與中醫甲、B1／B2 中醫乙與學士後中醫、C 牙醫三）、國考複習、實驗課；4:3（10×7.5 in）與 16:9（13.33×7.5 in）；我們用 scripts/ 管線（pool.md＋gen_pptx.py）或 ENT 的 成品/工具腳本 產生、交給他的 deck；他親手改過之後的回灌。
- **課程明令**：目前只有課程 C（immune）；明令只在該課有效（01 AUTH-02），各檔以「使用者（教師）2026-09 明令」標示。
- **不適用**：講義 HTML 與教案的版面；考試卷；他人（同事甲、同事乙）的投影片風格；事實內容本身（事實以 Robbins 11e 為準，見 01 AUTH-05 與各課 facts）。

## 規則（最重要的十條）

1. 衝突時照權威順序：他親手改我的稿 ＞ 他自製 2026 ＞ 2025 ＞ 2024 ＞ 課程明令（只管該課）＞ 我的毛胚 ＞ 他人；舊記憶檔與 CLAUDE.md 的說法以本指南為準。（AUTH-01、AUTH-02、AUTH-06）
2. 不寫 LLM 語：套語、全形雙破折、舞台指示、打氣、結構標籤一律 0；他自己的「其實」「不是 X，而是 Y」「因此」照用。（BAN-03、SYM-01、BAN-14、BAN-34、BAN-15、TONE-35）
3. 術語寫「中文(English)」，半形括號、同段同字級；dysplasia 一律「分化不良」；染色名、CD、Ig、HLA／MHC 只寫英文（課程 C 明令每張中英另計）。（TERM-01、TERM-02、TERM-03、TERM-34）
4. 一張講一件事、字少：內文 ≥30pt 的張 ≤150 字元、不放 6 條以上條列，新寫的張 0–3 條；放不下就拆同標題連張，不縮字。（DEN-02、DEN-10、DEN-03、DEN-27）
5. 同一件事分 2–6 張逐字相同的標題慢慢揭露，每張只改一件事，不加「(續)」，不用動畫與轉場。（TTL-04、RHY-01、RHY-02、RHY-29、RHY-35）
6. 圖要多、要大：形態學大堂課有圖率約 65%，4:3 單圖面積 ≥17 平方吋；不產佔位張或佔位框，缺圖就做全寬純文字張。（IMG-01、IMG-03、IMG-02）
7. 不做學習目標、大綱、總結、Q&A、謝謝、參考文獻張，投影片停在最後一個內容張；封面不署名。（OPEN-03、OPEN-22、OPEN-02、CITE-17、OPEN-01）
8. 國考題：題幹與選項照題庫原文，年次、題號、正解由題庫 key 產生，甲式首欄正解字母粗體；不考醫師國考的 B 班不放醫師題。（EXAM-02、EXAM-26、EXAM-04、EXAM-23、EXAM-40）
9. 他的句子逐字沿用、錯字照留；事實依 Robbins 11e，他的舊張錯誤與所有改動列進待教師裁決清單，不靜默改也不靜默沿用；學生要看的東西放投影片，備註可短可空、不當驗收。（QUOTE-39、TERM-18、AUTH-05、AUD-36、NOTE-01、NOTE-02）
10. 綠燈不算數：跑完 check_deck、style_check、verify_quotes 之後，渲染 PNG 逐張看溢出、孤字、行首標點與被壓小的圖。（LAY-35、DEN-28、52_交付前檢查清單）

## 規則格式說明

### 規則九欄

每條規則固定寫成：

```
### <ID> <一句話指令>
- 等級：MUST／SHOULD／MAY／AVOID／NEVER
- 門檻：<數字或「無」>
- 適用範圍：<畫幅／課程代碼／張型／體裁>
- 他的正例：「原文」（語料代號 #張號）…（逐字，1–4 例）
- 我的反例：「原文」（語料代號 #張號）→ 他改成「…」（語料代號 #張號）…（有證據時）
- 機械檢查：<regex／metric／manual>（對應 style/rules.yaml id，若有）
- 為什麼：…
- 證據強度：<計數與分母，去重後的套數>
- 例外：…
```

- **ID**：前綴＋兩位數字，前綴見檔案地圖。編號沿用挖掘檔，不代表強弱；檔內依等級與證據強度排序。
- **一句話指令**：可以直接照做的祈使句；讀不完全文時至少照這句做。
- **適用範圍**：寫明畫幅、課程代碼（A1、B2、C…）、張型（divider、國考張…）或體裁（大堂課、國考複習、實驗課、B2 改寫型）。「B2 改寫型」指沿用我的 ENT／lung 模板、經他親手改稿核定的 deck。
- **他的正例／我的反例**：一律逐字。「↵」「⏎」是原檔軟換行，比對時忽略。
- **機械檢查**：regex 以 Python re 語法寫；metric 寫計算方式；manual 表示只能人工看（多半要看渲染後的 PNG）。

### 等級定義（全指南通用）

| 等級 | 意思 | rules.yaml 對應 |
|---|---|---|
| MUST | 違反就會被他改，或違反他對該課的明令，或會造成事實、班別版本錯誤 | RED |
| NEVER | 他的語料 0 次、改稿一律刪或改；出現即不得交付 | RED |
| SHOULD | 強烈傾向；偏離要有理由並寫在交付說明或待教師裁決清單 | 通常不入 rules.yaml；有數字門檻的放 other_checks（WARN） |
| AVOID | 不要生成；他自己偶有、或只在他人檔出現 | WARN |
| MAY | 他的可選做法，可以用也可以不用 | 不入 rules.yaml |

少數規則的等級欄帶括號說明（例：「MUST（限課程 C）」），括號是適用範圍的補充，以括號前的字為準。

### 引句格式與核對

- 引句一律寫成「原文」（語料代號 #張號），例如「炎 = 火 + 火」（2026_A1_發炎一_0917 #39）。代號見 90_證據索引.md；張號是原檔的投影片序號。
- 核對：`cd scripts && PYTHONIOENCODING=utf-8 python verify_quotes.py <檔或資料夾>`；比對時忽略空白、換行記號與全半形括號，找不到代號、張號或原文都報 FAIL。
- verify_quotes 的正則只抓 2–300 字、不含「」的引句。引句裡有巢狀「」（古籍條文）、只有一個字、或超過 300 字時不會被核對到，要人工對 <materials>/corpus/decks/<代號>.json，並在該處註明「（人工核對）」。
- 不在語料裡的來源（課程 C 成品、審查報告、immune/brief.md）不用這個格式，改寫檔名與段落（例：immune/_archive/review/round1/fix_report.md，terms-13），免得被當成語料引句核對。

### 唯一出處、別名與 v0 舊 id

- 同一件事只在一個檔當「唯一出處」寫門檻與 regex，其他檔寫「見 XX-NN」或標「別名」。檢查器只跑唯一出處那一條（例：佔位字的 canonical id 是 IMG-02，LAY-13、CUT-01、EDIT-02、CX-01 是別名）。
- style/rules.yaml v0（2026-09-24）的 18 個舊 id 中 15 個與本指南同號不同義。指南裡稱舊條目一律寫「v0:」前綴（v0:BAN-07＝戲劇化第二人稱；指南 BAN-07＝口號類比）。rules.yaml v1 保留舊 id 與內容，每條加 guide_id 欄；新條目用指南 ID，指南 ID 已被 v0 佔用時加「g」（BAN-07g＝指南 BAN-07），同一條規則的次一級檢查加「w」（WARN 級）或「s」（只查投影片的那一級）。
- 43_反例庫 用 CX 前綴，每組反例指向規則本體，不另立門檻。01_權威順序 用 AUTH 前綴。

### 語料群組名

EDITED＝他親手改我的稿（改後）、HIS＝他自製、明令＝他對特定課程的明令、MINE＝我的毛胚、OTHER＝他人（同事甲的檔與他檔內的同事甲舊張段）。定義與去重對照見 01_權威順序.md。

## 版本與更新規則

他親手改了一份新 deck（或回覆了待教師裁決清單）之後，照下列順序把新證據放進指南：

1. **登錄語料**：在私人 repo 的 `corpus/corpus_list.tsv` 加一行「代號<TAB>pptx 路徑」。代號規則 {年}_{課程碼}_{主題}_{日期}；我的原稿用 mine_ 前綴，他人用 other_ 前綴。
2. **傾印**：`cd "<kit>/scripts" && PYTHONIOENCODING=utf-8 python dump_pptx.py <pptx> "<materials>/corpus/decks/<代號>"`（產 .json 與 .txt；整批重傾印用 `--batch "<materials>/corpus/corpus_list.tsv" "<materials>/corpus/decks/"`）。語料一律寫進私人 repo，不要寫到 `<kit>/style/corpus/`（被 .gitignore 排除，有私人 repo 時工具也不讀）。
3. **比對**：`python diff_decks.py "<materials>/corpus/decks/<我的原稿>.json" "<materials>/corpus/decks/<他改後>.json" "<materials>/corpus/edits/<名稱>.md" --layout "<成品>/<交件檔名>_layout.json"`（毛胚只比一部分時加 `--range a-b`）。diff_decks 以全文相似度配對新舊張；`--layout` 讓每個「原#N」標出素材池 slug，並多一張「新#→原#→slug」對照表（B2 舊專案沒有 layout 檔，改用備註的「投影片 N｜」表頭）。相似度配對的張要人工確認（42 EDIT-42）。
4. **更新索引**：私人 repo `corpus/index.md` 的語料表與「改稿對照」表（張數、畫幅、有圖率、字元中位、刪／增／對應），90_證據索引.md 的語料清單。
5. **定權威級**：他親手改我的稿屬最高一級；他沒動到的張不算接受（AUTH-03）；改到課程明令的項目（字級、每張中英、國考題數）只更新該課程的條目，不外推（AUTH-02）。
6. **逐檔更新**：在對應主題檔改規則的門檻、正例、反例、證據強度與統計表，改 last_verified；新規則編下一個號，不重用舊號；被推翻的說法補進 01_權威順序.md「已被推翻的舊規則」。
7. **同步 rules.yaml**：凡改到「機械檢查」欄的 regex 或門檻，照 style/rules.yaml 檔頭的 id 規則改那一條；新 regex 先對他自製檔跑一次，命中他的句子就改寫成詞組或降 WARN（23 BAN-30）。驗證：`python -c "import yaml;yaml.safe_load(open(r'<kit>/style/rules.yaml',encoding='utf-8'))"`，再跑 `python style_check.py --course <課程>`。
8. **核對引句**：`PYTHONIOENCODING=utf-8 python verify_quotes.py`（不帶參數即檢查整個 style/guide），FAIL 要修到 0；巢狀引句照上方「引句格式與核對」人工核。
9. **回灌來源檔**：他改的內容回灌該課 pool.md／script.md 後重產（immune/CLAUDE.md 待辦、42 EDIT-42），不手改成品。
10. **更新本檔**：統計表的規則數、語料數與 verify_quotes 結果，last_verified 改成當天。

大改（新增一整個面向、或一份新改稿推翻多條規則）時，可以重跑 workflows/style-guide.js 的對應階段；挖掘原始檔在私人 repo `style_evidence/mining/`，不要覆蓋，新版另存。

## 常見錯誤

1. 讀了舊 ENT 專案的 CLAUDE.md（不是本 kit 的 CLAUDE.md）或舊記憶檔的「硬規則 v3」就照做（甲式正解字母不粗體、橘色不用、出處 9–14pt、每張 ≤200 字元）。→ 那些是舊推論，照 01_權威順序 的對照表與各檔規則。
2. 把課程 C 的明令（標題 36、內文 28、每張中英、牙醫師題）當成他的一般習慣。→ 只管課程 C（AUTH-02）。
3. 只讀規則的第一句，漏讀「例外」：例如「其實」「不是 X，而是 Y」「求救、召喚」這類他的用語被當成 LLM 語刪掉。→ 放行詞見 23 BAN-15、BAN-26、BAN-29。
4. 別名與唯一出處各跑一次檢查，同一處報兩次、兩種等級。→ 只跑唯一出處那一條。
5. 把 v0 舊 id 當指南 id 讀。→ 指南寫「v0:」前綴；rules.yaml 看 guide_id 欄。
6. check_deck、style_check 全綠就交付。→ 還要渲染 PNG 逐張看（LAY-35、DEN-28），並做一輪人工文風審查（23 BAN-36）。
7. rules.yaml 的 WARN 全部略過。→ 對從零新寫的 deck，標了 guide_check_level: FAIL 的 WARN 要逐條改掉；其餘 WARN 逐條看過再決定。
8. 把他改稿裡沒刪的我的寫法當成他的偏好。→ AUTH-03。
9. 從同事甲的檔或他檔內的同事甲舊張取例句。→ AUTH-04。
10. 把學生要看的事實、更正或正解寫在備註裡當作已交代。→ NOTE-02、NOTE-31。
