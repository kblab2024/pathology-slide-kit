# 備註

## 摘要

他幾乎不寫、也不讀備註：他自製去重 19 套（HIS）1,536 張只有 121 張有備註（7.9%），唯一備註 78 則；本檔張級統計用的代表套 1,561 張是 104 張（6.7%），各種算法的對照見 S1；16 個內容家族有 8 個整族 0 則（含封面署名同事甲的腫瘤；照 HIS 排除它是 7/15）；2026 自製 16 套沒有一則新寫的備註（全部承自 2024／2025 舊版，唯一只見於 2026 的是一串數字殘渣）；改我的三套時 315 則備註 0 則改寫，他新增的 41 張裡 39 張帶著被複製張的舊講稿、2 張空白；他 2026 新寫的評語 3/3 都寫在投影片上。所以最重要的是：備註不是驗收項（NOTE-01）；學生要看的東西一律上投影片，放不下就刪或加同標題連張，不要移進備註當作已交代（NOTE-02、NOTE-23、NOTE-31）；LLM 寫的備註要在他插刪、複製張之後仍然不出錯，也就是不寫張號、每則自含、不綁開課時間、不用會隨版型改變的方位去指畫面（NOTE-03、NOTE-04、NOTE-09、NOTE-28）；備註裡的事實要跟投影片和 Robbins 一致，投影片一改就同步，因為 script.md 會變成下一版講義（NOTE-30）；備註是他的提詞，不寫給他的留言或流程行話（NOTE-29）。如果要模仿他的備註，那是一兩句口語提詞卡：中文為主的 53 則中位 38 字、句尾多半不加標點、單段不分點，內容是講解句、圖片「看什麼」、考試吐槽、板書指令，偶爾 SmartArt 定義連張每步一句；他的英文原文貼文、聽打錯字、半句、殘渣與「上次／下次」是舊習或痕跡，LLM 不模仿，回灌時原樣保留但不學進 pool。2026-09 為牙醫系 C 班做的免疫疾病稿（184 張，尚未經他改）驗證了幾件事也暴露了新問題：新 pipeline 的 notes_map 不再寫「投影片 N｜」，張號 0/184，審查代理三次建議寫張號或「接上一張」都被改掉；但講稿中位 88 字（他 38 字）、41 則帶整段英文書目、31 則用方位、列序或顏色指畫面而其中 5 條被審查抓到與渲染後的投影片不符、2 則出現寫給教師的待裁決備忘與「round1 審查」流程字、5 條事實問題（把 Robbins 說法寫成現行做法、文獻結論說過頭、頁碼與圖源錯），另外約 20 處為了 28pt 放得下把內容移進講稿，其中 8 項只好在待教師裁決清單問他該放投影片還是只放講稿。挖掘稿有幾處被推翻：「SmartArt 無字張必須有備註」是傾印檔沒收 SmartArt 字的假象；「備註前載」只在 5/11 套成立；「第一人稱」與「術語第一次出現必寫中文(English)」都不是他的備註習慣。

## 規則

### 讀法（先看）

- 引文一律逐字，格式「原文」（語料代號 #張號），取自 `<materials>/corpus/decks/<代號>.json` 該張的標題、文字框、表格或備註；可用 `scripts/verify_quotes.py` 核對（去空白、全半形括號比對）。「⏎」代表原檔換行。
- 『』＝語料外的逐字文字：原檔 SmartArt 的 `ppt/diagrams/data*.xml`（傾印檔沒收）、我的免疫稿成品與審查報告。這些不在語料裡，後面寫路徑、張號或 slug，不用「（代號 #張號）」格式，verify_quotes 不核對。
- 免疫稿的張號：「成品第 N 張」＝ `immune/成品/病理學C_免疫疾病(PPTX)_20261002.pptx` 的張序；「審查當時第 N 張」＝審查報告裡的張號（之後可能移動），以 slug 為準。
- **權威順序**（規則衝突時一律照這個順序裁決）：他親手改我的稿 ＞ 他自製 2026 ＞ 2025 ＞ 2024 ＞ 他對某門課的明令（只管那門課）＞ 我的毛胚（只當反例）＞ 他人（只當對照）。備註這個維度有個特殊處：他改稿時從不動備註，所以「他親手改我的稿」這一層對備註只提供兩種證據：他怎麼改投影片（事實、術語、評語都改在投影片上），以及他複製、插入張時備註怎麼跟著跑。
- **「使用者（教師）2026-09 明令」**：他對某一班直接下的指示，目前是牙醫系 C 班免疫疾病（`immune/brief.md` 教師已裁決表、`immune/course.yaml`）：一個 4:3 檔三節約 180 張、每節 40 分鐘講完、牙醫師國考題就近嵌入、Robbins 11e 第 6 章是唯一正典、文獻只補充並必須引出處且不得蓋過 Robbins、衝突列清單交他、不可 LLM 語、字不可小（標題 36、內文 28、學生要讀的字 ≥20、出處 14）、所有專有名詞「中文(English)」。這些明令都沒有直接講備註；與備註有關的是「不可 LLM 語」「文獻必引出處、衝突列清單」（NOTE-14、NOTE-30）和字級（間接造成 NOTE-31 的溢流壓力）。「中文(English)」明令在 glossary 寫明是管投影片，不管備註（NOTE-21）。
- **「免疫稿經驗」**：我 2026-09 產的 C 班免疫稿與兩輪審查的發現。這份稿還沒經他改，屬「我的毛胚」層：只能當反例與流程教訓，不能當他的正例。免疫稿的講稿格式「Robbins 頁碼＋1–2 句提示」是 writer brief §5 與 `immune/CLAUDE.md` 訂的 pipeline 規格，不是他的明令。
- 等級：MUST＝必須；NEVER＝禁止；SHOULD＝應該，偏離要有理由；AVOID＝避免，偶爾可以；MAY＝他用過、可選用。
- ID 沿用探勘版（`<materials>/style_evidence/mining/36_備註_final`）的 NOTE-01 到 NOTE-27，其他指南檔的交叉引用都指這組號碼；NOTE-28 到 NOTE-31 是本版依免疫稿新增。
- 「LLM 產出」＝我或任何代理寫的備註與 script.md 講稿、講義補充；「他的備註」＝他自製檔裡的備註。大多數 FAIL／WARN 只掃 LLM 產出，不回頭檢查他的檔。
- 分母與群組標籤（詳見統計表 S0；標籤與全指南共用：HIS＝他自製去重、EDITED＝他親手改我的三套、MINE＝我的毛胚、OTHER＝他人、REVIEW＝國考複習）：HIS 19 套 1,536 張（本檔張級統計另用代表套 19 套 1,561 張，差別見 S0、S1）；他自製唯一備註 78 則（中文為主 53、中文／混合 58，兩種母體相同）；EDITED 317 張；MINE 417 張；OTHER 96 張；免疫稿 184 張（語料外）。備註覆蓋率的唯一出處是 S1，其他檔引用時寫「見 36_備註 S1」，不另算。
- `style/rules.yaml` v0 與備註有關的只有 scope 為 notes 或 all 的幾條（SYM-01、BAN-01、BAN-02、BAN-03、BAN-06、BAN-07、TERM-01），沒有 NOTE 前綴的 id；`style_check.py` 用這幾條掃 script.md 的【講稿】與【講義補充】（題目張不掃），glossary 的禁用變體與中英檢查只掃投影片。各條「機械檢查」寫了對應 id，沒有就寫「rules.yaml 無對應 id」，由 50_檢查 重生 rules.yaml 時補。

### 規則速查（依強度排列）

| ID | 等級 | 規則 |
|---|---|---|
| NOTE-01 | MUST | 把 PPTX 備註當非驗收項：投影片本身必須不靠備註就完整，備註覆蓋率不設下限，缺備註不算缺。 |
| NOTE-03 | MUST | LLM 產出的備註不寫會因插刪張而失真的張序指涉：不寫「投影片 N｜」「第 N 張」，也不寫「上一張／下一張／前一張／後一張」。 |
| NOTE-18 | MUST | 不得把他備註裡的錯字與語助殘留學進 pool、句庫或講稿；備註錯字屬輸入錯誤，不適用「他的錯字沿用」規則。 |
| NOTE-02 | NEVER | 不要指望他讀、改或校對備註：學生必須看到的事實、定義、數字更正、國考正解與出處一律放在投影片上，備註只放投影片已有內容的口語版。 |
| NOTE-14 | NEVER | 備註同樣禁 LLM 裝置語：不用全形雙破折號、其一其二、「這句話請記牢／記住這句」、「你已經知道／我還欠你們」式戲劇化第二人稱；glossary 禁用變體在備註也不用。 |
| NOTE-23 | SHOULD | 要讓學生看到的評論（方證對應、回頭看題、講義不夠要讀原文）寫在投影片上，當標題列或括號小句；只供口頭發揮的吐槽才放備註。 |
| NOTE-30 | SHOULD | 備註裡的事實、數字、術語要和投影片與 Robbins 一致，文獻句標來源、不說過頭；投影片一改，同張講稿與講義補充同步改；衝突列清單，不在講稿裡自行裁決。 |
| NOTE-04 | SHOULD | LLM 寫的每則備註要能獨立成立：只講這一張，不寫「講到喉再回來看」「接下來這張」式的跨張銜接，因為他複製張做漸進揭露時備註會整份跟著複製。 |
| NOTE-28 | SHOULD | 備註裡指畫面的話（第幾列、紅框、藍字、箭頭、左右上下圖）要對得上渲染後的這一張，投影片改版後同步改；位置優先用圖上看得到的標記或特徵。 |
| NOTE-12 | SHOULD | PPTX 備註寫成單段口語，不放 pipeline 元資料：〔講義補充〕區塊、書目條列、「國考出處：」、補充來源、slug、頁碼清單都留在 script.md 或講義。 |
| NOTE-29 | SHOULD | 備註是他的提詞，不寫給他的話：待裁決問題、審查紀錄、授權、圖源與用詞備忘、「封面已致謝」「可不標」一律放待教師裁決清單或工作檔。 |
| NOTE-06 | SHOULD | 備註寫成他上課說話的口語：可以用我們／各位／你們／你，也可以用「X(English)的意思是…」定義句或無主詞短提示；不寫「本張／本節／本段／以下說明／學生應」這類書面說明語。 |
| NOTE-09 | SHOULD | 跨堂或跨科銜接用主題指涉（栓塞後面會講、發炎時講過的滲出液、這會出在微免），不用星期、上次／下次、上一堂／下一堂、下一節這類綁開課時間或張序的詞。 |
| NOTE-24 | SHOULD | 回灌他改過或自製的檔時，備註只當「可能屬於來源張」的附件：剝除「投影片 N｜」前綴，首句與張標題對不上的另存 orphan 清單，不直接寫進該 slug 的講稿。 |
| NOTE-31 | SHOULD | 投影片放不下時，學生要看的內容不移進備註當作已交代：先刪、拆成同標題連張或改圖；真要移進講稿，就在待教師裁決清單列一項。 |

| NOTE-20 | SHOULD | 國考複習與實驗課 deck 的 PPTX 備註預設留空；各論大堂課也不替每張補講稿，是否放講稿依使用者的 pipeline。 |
